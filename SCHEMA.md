# Synthetic dataset schema

Everything under `data/synthetic/` is generated by `milo/synth.py` (`python scripts/regen_dataset.py`,
seeded with `numpy.random.default_rng`). No row of it is real: sellers, staff, card names, sets, prices
and order numbers are all invented. The layout mirrors what the loaders in `milo/load.py` and
`milo/market.py` consume:

```
data/synthetic/
  MANIFEST.json            generator knobs and row counts for this dataset
  raw/                     the "exported" store + market-feed files
  inputs/                  the three hand-edited input files
```

Generator knobs (`milo.synth.generate_dataset`): `seed`, `n_products`, `weeks`, `start`,
`demand_spread` (lognormal sigma of weekly rates across items), `elasticity_strength`
(scales every item's price elasticity; 0 = price never matters), `budget` (price scale anchor:
all prices/costs scale by budget/5000 so the default restock budget stays binding at any scale).

## Committed dataset knobs

The committed dataset is generated by `python scripts/regen_dataset.py` from
`milo.synth.DEFAULTS`: `seed=19`, `n_products=24`, `weeks=15`, `start="2026-07-06"`,
`demand_spread=1.4`, `elasticity_strength=1.6`, `budget=5000.0`. The seed and the two
shape knobs were retuned from provisional values (`11` / `1.0` / `1.0`) until the
acceptance bands held on the regenerated dataset: VSS >= 2% of RP, a measured
greedy-vs-MILP gap >= 2% at at least one budget, and EVPI > 0 (the measured values are
written by code into `reports/numbers.json`; all are in-sample, conditional on the
pinned scenario set). The dataset, the E2E goldens (`scripts/regen_goldens.py`) and
`reports/numbers.json` were regenerated together in one freeze and are not regenerated
again afterwards.

## raw/seller_a_sales.csv, raw/seller_b_sales.csv

One row per stock event for that seller, consumed by `load.load_store_events`.

| column | meaning |
| --- | --- |
| `Date (PT)` | event timestamp, `YYYY-MM-DD HH:MM` (store-local time) |
| `Kind` | `sale`, `stock_in` or `stock_out` |
| `Order` | order id (`ORD-<number>`) for sales; empty for stock events |
| `Product` | listing title, in that seller's title grammar (see `milo/catalog.py`) |
| `Variant` | listing variant (`Default Title` when none; the set name for family products) |
| `SKU` | seller SKU (`SKU-NNNN`); may be empty |
| `Units` | units moved (positive integer) |
| `List price` | listed unit price at the event |
| `Revenue at list` | `Units x List price` |
| `By` | synthetic staff label (`Register - <name>` / `Web Import - <name>`) |
| `Location` | always `Main St` |
| `Reason` | `Initial inventory`, `Received restock`, `Damaged`, or empty for sales |

## raw/restock/restock_events.csv

One row per `stock_in`, consumed by `load.attach_sell_dates`. Joined back to the sales files on
(`Vendor` lowercased with spaces -> underscores, `Entered (PT)` floored to the minute, `Product`,
`Variant`, `Units`), so those five values match the stock_in rows exactly.

Columns: `Vendor` (`Seller A`/`Seller B`), `Entered (PT)`, `First selling day` (a date; the next
open day for after-hours uploads, else the entry date), `Product`, `Variant`, `SKU`, `Units`,
`Catch-up units`, `List price`, `Reason`, `By`.

## raw/restock/{sold_out, restock_soon, shared_products, restock_days}.csv

Reporting tables copied as-is by `load.load_restock_tables` (displayed, never recomputed).
Headers:

- `sold_out.csv`: `Vendor, Product, Variant, SKU, Price, Sold, Days in stock, Steady days,
  Steady sale days, Bulk units left out, Days out, Sold per steady day, Other vendor units while out,
  Other vendor $ while out, Days store had none, Est missed units, Est missed $, Out now`
- `restock_soon.csv`: `Vendor, Product, Variant, SKU, On shelf now, Arriving, Lands,
  Sold per in-stock day, In-stock days, Sale days, Bulk units left out, Days of cover,
  Days of cover with arriving`
- `shared_products.csv`: `Type, Set, Seller A prices, Seller B prices, Seller A sold, Seller B sold,
  Days Seller A in stock, Days Seller B in stock, Days both out`
- `restock_days.csv`: `Date, Day, Kind, Vendor, Store orders (est), Orders, Items, $,
  Restock new units, Restock new $, Restock day, Open days since restock, Shelf units at open,
  Items in stock at open, Shelf $ at open, Shared products in stock`

All four are optional: when absent, `load_restock_tables` returns `{}` and `attach_sell_dates`
falls back to the entry date.

## raw/commission/*.xlsx

Weekly commission workbooks (primary seller only), consumed by `load.load_commission_lines`.
Real `openpyxl` workbooks: a few preamble text rows, then a header row **found by the literal
first cell `Order #`**, then one row per item line, then a `TOTAL` row (skipped by the loader).

Header columns the loader renames: `Order #`, `Date`, `SKU`, `Item`, `Qty`, `Unit price`, `Sold`,
`Order paid by`, `Note`. The paid-by column header must be EXACTLY `Order paid by`: any other
spelling is silently absorbed by the loader's `fillna("Card")` default and corrupts the card-fee
share without an error. The oldest committed workbook deliberately predates the paid-by column;
its lines count as card, which is the workbook's own default. One line per workbook carries a
SKU containing `custom` (a register-rung custom item).

## raw/order_ledger.csv

Store orders holding tracked sellers' items, consumed by `load.load_order_ledger` and
`demand.store_orders_per_day`. Columns: `Order` (`ORD-<number>`), `Number` (store-wide sequential
order number: plain integer, no prefix; gaps between our orders are other vendors' orders),
`Time UTC`, `Time PT`, `Register sale` (`yes`/`no`), `Staff`.

## raw/store_daily.csv (optional)

Whole-store orders per day, consumed by `load.load_store_daily` (returns None when absent).
Columns: `Date`, `Day` (`Mon`..`Sun`), `Kind` (`full`/`partial`; partial days are skipped by the
traffic step), `Store orders (est)`.

## raw/store_weekday.csv (optional)

Average store orders per weekday, consumed by `load.load_weekday_shares` (returns None when
absent). Columns: `Weekday`, `Full days`, `Avg store orders`. The loader zeroes the closed
weekdays' share (from `StoreConfig.store_closed_weekdays`) and normalizes the rest to sum to 1.

## raw/sold_products.csv

Every in-scope product with at least one sale, written by round-tripping the generated sales
files through `load.load_store_events` -> `catalog.build_catalog` -> `tcgmap.sold_products`,
then assigning stable keys `P000`, `P001`, ... in (product, variant) order. The pipeline reads
only `key`, `product`, `variant` (plus `first_sale`/`last_sale` as dates) and re-derives the
parsed columns from today's catalog; the keys tie products to `inputs/tcg_map.csv`.

Columns: `product, variant, units_sold, list_price, seller, sku, first_sale, last_sale,
product_type, set_raw, condition, game, set, is_single, set_source, family, in_scope,
needs_review, key`.

## raw/unit_costs.csv

The seller's unit-cost sheet, consumed by `load.load_unit_costs`. Columns: `SKU`, `Cost (ea)`,
`Ask`, `Market (ea)`, `Set`, `Format`, `Product type`, `Date In`. The three money columns mix
plain numbers with `$`-and-comma strings (e.g. `$1,234.56`); the loader strips `[$,]` before
parsing, and the committed data exercises that path. `Set` supplies the set for singles whose
title has no set segment (`set_source == "ledger"` in the catalog). Two mapped items are
deliberately missing from this sheet so the pipeline's default-cost path
(`DEFAULT_COST_SHARE x market price`) stays live.

## raw/set_release_dates.csv (optional)

Canonical set names and release dates, consumed by `load.load_set_release_dates` (returns None
when absent; nothing downstream requires it). Columns: `set`, `release_date`.

## raw/tcg_sales/<id>_<date>.jsonl

One json line per fetched sales page from the market feed, consumed by `market.sales_table`:

```json
{"id": 100001, "offset": 0, "fetched_at": "2026-10-20",
 "page": {"previousPage": "", "nextPage": "", "resultCount": N, "totalResults": N,
          "data": [{"condition": "Near Mint", "variant": "Normal", "language": "English",
                    "quantity": 1, "title": "...", "listingType": "ListingWithoutPhotos",
                    "customListingId": "0", "purchasePrice": 3.83, "shippingPrice": 0.0,
                    "orderDate": "2026-10-19T02:03:00+00:00"}, ...]}}
```

The committed files hold the last 21 days of individual sales per mapped product. Conditions
use the feed's names (`Unopened`, `Near Mint`, `Lightly Played`, ...), matched from store
conditions via `compare.CONDITION_TO_TCG`.

## raw/tcg_history/<id>_<date>.jsonl

One json line per chart range (`month` = daily buckets, `quarter` = 3-day, `semi-annual` and
`annual` = weekly), consumed by `market.chart_table`:

```json
{"id": 100001, "range": "month", "fetched_at": "2026-10-20",
 "chart": {"count": 1, "result": [{"skuId": 1000010, "variant": "Normal", "language": "English",
    "condition": "Near Mint", "buckets": [{"marketPrice": "2.1", "quantitySold": "1",
      "lowSalePrice": "...", "lowSalePriceWithShipping": "...", "highSalePrice": "...",
      "highSalePriceWithShipping": "...", "transactionCount": "1",
      "bucketStartDate": "2026-10-19"}, ...]}]}}
```

Bucket values are strings, as the feed sends them. Every range ends with a still-running bucket
starting on the fetch date, which `chart_table` must drop (M17b). `market.daily_market` stitches
finest-first: individual sales where present, else daily, else 3-day, else weekly buckets.

## inputs/tcg_map.csv

Product-key -> feed-id mapping, consumed by `load.load_tcg_map`. Columns: `key` (matches
`sold_products.csv`), `status` (only `ok` rows are used; the generator writes a `review`
row only when a blister sells, and with the committed knobs none does — the committed
file is all-`ok` rows; the filter is covered by a unit test), `tcg_id`, `product`,
`variant`, `note`.

## inputs/catalog_overrides.csv

Manual parser fixes, consumed by `catalog.load_overrides`. Columns: `product`, `variant`,
`product_type`, `set`, `condition`, `game` (blank = keep the parsed value). The committed file
fixes one deliberately odd title that parses to `other_sealed`. The pipeline reads this path on
every run; the file may be header-only but must exist in a complete dataset.

## inputs/restock_costs.csv

Hand-edited buy limits per demand unit, read by `pipeline.restock_units` (keep-if-exists
semantics: `pipeline.write_cost_template` writes a fresh template only when the target file does
not exist, and never overwrites your edits; the pipeline itself only writes it when
`run(cost_template_path=...)` is passed, and demo/tests never write into the dataset).
Columns: `unit`, `product_type`, `price_now`, `market_price`, `cost`, `cost_source`,
`min_order`, `max_units`, `salvage_frac`. The committed file gives the booster box a
`min_order` of 6, so the min-order disjunction in the optimizer is live.
